建议采用**显式启用的异步执行路径，保留现有同步 API**。这项需求的主要难点是让命令调用、上下文有效期、取消传播和测试捕获具有一致的生命周期；仅在入口补一个 `await` 不够。

评估基于当前检出 `934813e`，版本为 Click 8.1.8，并非对最新 Click 的判断。使用了架构 Skill；没有适用的 Python 异步技术 Skill，按你的授权参考了仓库内 Pallets/Click `docs`。这些文档能确认现有契约，但不能替代异步运行时的完整版本验证。

当前能力与证据如下：

| 边界 | 已核实事实 | 设计影响 |
|---|---|---|
| 命令调用 | [`Context.invoke`](/evaluation-path/repository/src/click/core.py:737) 创建子上下文、补齐默认值并转换类型，然后直接返回回调结果；`forward` 复用它。 | 已有可扩展接口，但等待必须发生在子上下文退出之前。 |
| 命令组 | [`MultiCommand.invoke`](/evaluation-path/repository/src/click/core.py:1663) 编排组回调、子命令、chain 和结果回调。 | 异步化必须覆盖整个编排；chain 仍应按顺序执行。 |
| 当前上下文 | [`globals.py`](/evaluation-path/repository/src/click/globals.py:9) 使用线程局部的可变列表保存上下文栈。 | 同线程异步任务交错时不能隔离上下文。 |
| 资源清理 | [`Context`](/evaluation-path/repository/src/click/core.py:462) 通过嵌套深度和同步 `ExitStack` 清理，先关闭再弹栈。 | 已有同步资源管理，缺少等待异步清理的路径。 |
| 测试 | [`CliRunner`](/evaluation-path/repository/src/click/testing.py:398) 同步调用 `main`；隔离会替换进程级输入输出、环境和部分 Click 函数。 | 新增异步 runner 不会自动获得并发安全。 |

三个只读内存探针在 Python 3.9.6、仓库源码上进一步确认：

- `async def` 命令经 `main(..., standalone_mode=False)` 返回协程对象，函数体没有执行，上下文已经退出。
- 先 `ctx.invoke(child)`、再等待返回的协程，子命令函数体读到的是父上下文。
- 同线程内两个任务交错进入不同上下文，任务 A 能读到任务 B 的上下文。

还有两个容易漏掉的兼容点：[`pass_context` 等装饰器](/evaluation-path/repository/src/click/decorators.py:27) 用普通函数包装回调，所以仅检查 `iscoroutinefunction` 不足；[`result_callback` 的组合包装](/evaluation-path/repository/src/click/core.py:1604) 直接把前一个结果传给后一个，异步模式需要逐个等待。

方案比较以同步兼容、取消后的清理正确性、上下文隔离、可维护性为优先顺序：

| 方案 | 收益 | 风险与适用范围 |
|---|---|---|
| 在回调外围包装 `asyncio.run` | 改动小，可以验证独立叶命令 | 多次建循环，难以共享异步资源；嵌套调用和已有循环中的调用受限。适合局部验证。 |
| 把现有调用链整体改成异步 | 编排模型统一 | 改变返回类型、调用方式及自定义子类契约，与同步兼容目标冲突。 |
| **新增异步入口，显式启用** | 旧调用路径稳定，可逐组迁移 | 两种路径需要共同验证，部分编排可能重复。推荐。 |
| 在独立扩展中先验证 | 核心初期改动少 | 上下文存储仍需核心配合；长期复制调用链会增加版本跟随成本。适合核心尚未承诺维护该能力时。 |

推荐方案可以利用已有 `cls`、`context_class`、`command_class` 和 `group_class` 扩展点，先引入 `AsyncCommand`、`AsyncGroup`、`AsyncContext`，名称作为提案。不要一开始抽象通用执行器或多个异步后端。

跨边界的契约建议这样确定：

1. **命令入口与转调。** 提供 `amain`、命令级 `ainvoke`，以及上下文级 `ainvoke/aforward`。上下文转调继续保留默认值转换、参数转发和自定义上下文类型；回调执行及等待都在目标上下文内部完成。异步组允许普通同步命令，但应保留其 `invoke` 覆盖行为。

   原有 API 继续同步返回。[现有文档允许任意返回值](/evaluation-path/repository/docs/commands.rst:564)，因此不能在旧路径上自动消费所有 awaitable。仅在显式异步回调位置归一化“普通结果或 awaitable”。同步回调向异步命令转调，应明确要求迁移到异步调用方式，不能靠嵌套运行循环补救。

2. **事件循环所有权。** 建议首版限定 `asyncio`，这是新设计选择。`amain` 使用调用方的循环；新异步命令的同步 `main` 只在顶层负责运行循环。已有循环中调用同步桥接，应在创建协程前给出明确错误并指向 `amain`。命令转调和 runner 不各自创建内层循环。

3. **上下文隔离。** 建议独立一步把当前上下文栈迁移到 `ContextVar`，使用不可变栈值，避免复制任务上下文后仍共享列表。所有同步、异步入口使用同一套存储，使装饰器和 `get_current_context` 保持一致。

   隔离“当前上下文指针”并不隔离 `Context` 对象：现有 `obj`、`meta`、参数和清理栈仍可共享。首版应限定一个调用上下文由一个执行任务负责，后台任务由应用管理。

4. **资源有效期与清理。** 在异步上下文中提供 `aclose` 和异步资源注册；同步、异步资源按统一注册顺序逆序清理。同步 scope 可以服务解析和嵌套调用，最终异步清理由外层异步 scope 承担。清理期间仍须能访问当前上下文，清理失败也必须恢复上下文栈；当前 `__exit__` 的 `close()` 与 `pop_context()` 之间没有 `finally`，不能直接照搬。

   需要保持既有生命周期差异：普通组在子命令上下文内处理结果；chain 则在各子命令退出后处理结果，不能统一延长所有子命令资源。[文档已有该限制](/evaluation-path/repository/docs/commands.rst:415)。

   chain 还会预先创建多个子上下文，而 [`File.convert`](/evaluation-path/repository/src/click/types.py:704) 可以在解析时打开资源。异步路径必须清理取消时尚未执行的已创建上下文，以及解析失败时已经取得的资源。

5. **取消与异常。** 首版以调用任务的取消作为入口，采用协作式取消；同步解析、提示和阻塞回调不会因此变成可抢占操作。取消应穿过转调和组编排，停止后续 chain 命令及成功结果处理，清理后向宿主传播。

   区分程序化取消与 CLI 中断：`amain` 向宿主传播取消；顶层同步入口的 Ctrl+C 沿用 Click 的 `Abort`／退出码 1 契约。异步清理须考虑再次取消，调用不能在清理任务仍运行时就恢复上下文或测试输出。原始失败与清理失败都要保留诊断信息，避免取消变成普通错误或成功。

6. **测试边界。** 新增 `CliRunner.ainvoke`，等待整个执行与清理过程后再生成 `Result`；外部对 runner 任务的取消应继续传播，普通异常仍按 `catch_exceptions` 处理。旧 `invoke` 行为保持。

   保留 runner 的串行限制：即使上下文任务隔离正确，`sys.stdout`、环境和工作目录仍属于进程。上下文并发测试应直接测试调用接口；并发 CLI 捕获使用独立进程。

增量实施与验收可以分为四步：

| 步骤 | 完成标准 | 回退边界 |
|---|---|---|
| 固定兼容基线 | 覆盖返回值、默认值转换、多级 forward、自定义子类、关闭前可访问上下文、group/chain 结果顺序。 | 尚未引入异步执行。 |
| 迁移上下文存储 | 原有同步测试通过；交错任务、嵌套 scope 和异常退出不串上下文。 | 可独立撤回存储迁移。 |
| 加入显式异步调用和清理 | 叶命令、转调、组、chain、组合结果回调逐项接入；取消后资源清理完成，后续命令不执行。 | 调用方保留同步命令注册；异步业务需同步实现才能业务回退。 |
| 加入异步 runner 并稳定发布 | 正常、失败、取消后都恢复捕获环境；无遗留执行／清理任务；文档写明混用边界。 | 可以保持异步功能显式启用，不切换默认行为。 |

取消测试应通过事件精确控制取消时点，覆盖等待中、结果回调中、清理中，以及再次取消和清理失败；不要依赖固定 `sleep`。已有测试能作为同步兼容基线，例如 [`test_custom_classes.py`](/evaluation-path/repository/tests/test_custom_classes.py:20) 和 [`test_context.py`](/evaluation-path/repository/tests/test_context.py:219)。

实施前仍需定案的是：是否接受首版仅支持 `asyncio`、异步清理的期限及再次中断策略、自定义命令覆盖的异步接入方式。当前声明支持 Python ≥3.7，tox 列出 3.7–3.13 与 PyPy；应保持该矩阵或单独决定调整版本范围，不能随异步功能隐含改变。
