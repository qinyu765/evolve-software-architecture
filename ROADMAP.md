# Roadmap

## v0.1 — Historical foundation

XiLuoLin established the evidence-first review, Desktop/Tauri reference, and release-pinned vendor workflow. AIRI and MarkText established independent desktop baselines, followed by v2/v2.1 factual-accuracy calibration and scorer provenance. Those results remain immutable historical evidence; the archived adapter strategy is superseded by ADR-0004.

## v0.2.0 — Generic architecture method

- Existing-repository reviews, structural refactoring, and substantial new requirements.
- Verified current-state evidence and discovery of already-implemented capabilities.
- Cooperation with applicable technology Skills instead of built-in framework adapters.
- User choice before substituting documentation when suitable Skills are missing; existing authorization is honored.
- Compact real-repository acceptance across AIRI and Click, including trigger precision, missing guidance, and conflicting advice.
- Same install target, implicit invocation policy, and reproducible vendor format; no automatic project-copy update.

Release requires package validation, existing automated checks, and independent factual/behavioral review of the new acceptance tasks. Historical Electron-only checks and a two-point score improvement are not this release's gates. See `evals/acceptance-v0.2.md` for the fixed acceptance protocol and result index.

## After v0.2.0 — Evidence-driven maintenance

Maintain a usable release rather than pursuing a schedule of new adapters. Change the core for a reproduced reasoning failure, false trigger, or companion-cooperation defect. Add a targeted regression case before expanding a rule. Verify affected behavior and cross-type consequences without rerunning unrelated historical experiments.

No framework catalog, automatic installer, built-in SDK/Web/CLI adapters, additional scorer matrix, or greenfield mode is planned. Reconsider a distinct lifecycle only when a real use case needs its own trigger, output, and validation.

## Promotion and release rules

- Repository-specific facts stay in the review or evaluation case.
- Framework practices stay in companion Skills or authorized documentation.
- New universal guidance requires portable reasoning or evidence across materially different project types; do not promote one project's preferred design.
- Preserve original answers, failed attempts, and scoring contracts; publish revised evaluations separately.
- Release upstream before updating any project copy, and retain drift protection.
